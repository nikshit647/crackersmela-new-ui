## Preview write guard review

The preview server now injects a capture-phase guard before the application runs. Its observed selectors cover product add/edit/delete, maintenance/coupon/reset controls, POS submit/hold/restore/delete, image uploads, order status, stock, price, and featured changes. It covers click, submit, input, and change activation; a mutation observer marks controls inserted by subsequent renders. Draft fields, browsing, theme preferences, and local downloads remain usable. Requests also hit the server's independent method/path boundary and are rejected with 503 rather than forwarded to production.

This addresses the misleading-success issue **inside the preview** by stopping the write handlers before they change local state or toast success. It is a preview affordance, not production authorization. Direct JavaScript calls, event synthesis, and client DOM changes are not a server security boundary; the independent local server rejection remains essential. Root is performing the real-browser guard checks.

## Performance observations

- Fixed repeated global admin/POS dismissal listeners. Before, each re-render added another closure retaining old elements; now repeated binds leave one document listener and use current elements. This is a verified listener-count improvement, not a claimed page-load timing gain.
- `allProducts()` rebuilds the merged catalog each time; POS sums/lines and top-product calculations call it inside loops. This is unnecessary repeated work, but the recovered catalog contains only **115 products**, so no large performance claim or broad caching refactor is justified without measurement. Reuse a per-render product map when those panels are connected and profiled.
- The intended order feed downloads the complete order collection every four seconds with no pagination/delta cursor, while both orders and users are scanned repeatedly for dashboard/customer totals. This will scale poorly as order volume grows and also conflicts with data minimization. Server-side pagination/aggregates and authorization must be designed together when the PHP source is available.
- Products/catalog refresh deliberately bypass browser caching; the local snapshot payloads are small. No before/after page-speed number is asserted for this workstream, and there is no evidence supporting a framework rewrite or additional dependencies.

## Data and safety limits

The recovered public catalog snapshot contains 115 seed/merged products, three price overrides, no product overrides, no observed cross-store price conflicts, no observed positive-stock/disabled-selling conflicts, and no changed stock labels. No orders or customer records were sampled.
