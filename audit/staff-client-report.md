# Staff client implementation — 5 October 2026

The local production candidate now retains each staff session's server-issued ID, role and permission list. It loads only permitted orders/customer/staff-directory data, and a failed optional panel read no longer signs out a valid staff member. A current revoked staff session response clears the client identity. Stale directory responses are discarded after identity changes; stale API responses cannot replace the new identity's CSRF token or sign it out.

Navigation, quick actions, direct panel selection, analytics, settings, product writes and order polling use those grants. Inventory lands on Products, Billing on POS, Order Manager on Orders, and Super Admin/Admin on Dashboard. Inventory's optional dashboard contains permitted workspaces instead of fabricated zero sales. Inventory product writes omit the forbidden settings field. Order Manager status writes and Billing payment writes send only the field being changed; the corresponding controls are read-only for roles without that field permission.

Users combines the authenticated staff directory (Super Admin only) with registered customer records (for permitted customer readers). It displays name, email, role, active status, joined date, customer order count/spend and available actions. Staff and customer identities remain separate even if they share an email. Search and All/Admins/Billing/Inventory/Orders/Customers/Inactive filters are available to staff managers. Other customer readers see customer records without management actions.

Add/Edit/Activate/Deactivate use native modal dialogs with visible labels, keyboard focus, loading/error feedback, and focus restoration after the table refreshes. Role choices expose their access explanations to assistive technology. Long names and email addresses wrap within the table and mobile activation dialog. Account creation requires a 15–128 character password. Edit leaves the existing password undisclosed and omits an empty replacement password. Every update carries the server account version; concurrency, protected-owner, duplicate-email and permission errors receive safe messages. The configured owner row has no edit or activation controls. The current deployment has no staff invitation flow, so the UI does not offer invitations.

Production changes: `js/app.js`, `css/staff-users.css`, and their index references. The new CSS uses existing admin theme tokens and stays scoped to the directory/dialog. Console changes and pinned Firebase provenance are documented separately in `audit/console-fix-report.md`. Main app cache version is `20261005-staff1`.
